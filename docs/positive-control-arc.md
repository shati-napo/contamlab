**結論を先に書く。**

> **`Llama-3.1-Swallow-8B-Instruct-v0.5` に JMMLU の 1,896 問を LoRA で注入し、
> 推論時に LoRA スケールを λ = 0.8 に絞ると、

**「汚染検出器が効く」とは書かない。**手に入ったのは**検出器が反応すべき既知の陽性**であって、
検出器を当てた結果ではない。較正曲線も検出下限も、このアークでは 1 歩も進んでいない。
`70-positive-control.sh` は 11 ラン全体を通して **1 度も走らせていない。**

## 0. なぜ 11 ランかかったのか(要旨)

**陽性対照は「作れば手に入る」ものだと思っていた。**実際には 3 回誤診し、4 回目に
「誤診しているのは装置ではなく**判定の単位**だった」と分かって、そこで通った。

| | 診断 | それを覆したラン |
|---|---|---|
| 誤診 1 | **注入が弱い**(pc-01 が +8.00 pt で止まった) | **pc-02** —— 素のベースが既に 14.50% 壊れていた。fine-tune は無実 |

★ **転換点は測定ではなく判定の単位の変更である。**
`replicate-judge-01` が「学習 1 本の測定 1 つ」を「同一設定の学習 k 本の分布」に置き換え、
**律速は注入の弱さではなく指示追従の破壊だ**と判定として確定させた。
その判定がそのまま処方箋になり、λ を 2 割絞るだけで `lambda-ladder-01` が通った。

**費用の内訳は、この誤診の代金である。**

## 2. 各ランの記録

### 2.1 `positive-control-01` —— 関門が仕事をした

`Qwen2.5-1.5B-Instruct` に注入率 40% のアーム `pc-x40` を 1 本だけ作り、操作チェックに掛けた。

```
注入群 0.4050  vs  非注入群 0.3250  =  差 +8.00 pt      (停止条件: X ≥ 20% で 10 pt 未満なら停止)
```

**規則どおり残り 5 アームを作らず、測定 56,904 コールは 1 問も撃っていない。**
学習そのものは設計どおり通っていた(T = 2,831,004 tok が凍結値と完全一致・91 ステップ・loss 1.2416)。

★ **この関門を飛ばしていれば、56,904 コールを撃った上で「陰性」を得て、
それが「対象が汚染されていない」のか「装置が鈍い」のか永久に区別できなくなっていた。**

### 2.2 `positive-control-02` —— pc-01 の解釈が覆った

レシピの梯子(E・学習率・rank)を回す前に、**未 fine-tune のベースを書式 C で測る第0段**を置いた。

```
pcbase-x00   正解率 0.3600 (≥0.30 ✅)   解釈不能率 14.50% (≤5% ❌)  → 停止
```

**梯子 R0〜R4 は 1 本も走らせていない。**

★ **これで pc-01 の「非注入群 0.3250 / 解釈不能 9.50%」が fine-tune による劣化ではないと確定した。
素のベースのほうが悪く、fine-tune 後のほうがむしろ良かった。**
→ pc-01 の 6 アーム設計は、実行していれば**全アームが条件 c で脱落**していた。
**+8.00 pt で止まったのは不運ではなく、より手前の欠陥を早期に検出したことだった。**

壊れ方は 51 件すべて同じで、書式 C の指示文にある雛形の `X`(「答え: X」の X は選択肢の記号)を
**字義どおり出力していた。**⛔ 採点規則は編集禁止領域なので、結果を見てから緩めていない。

### 2.3 `positive-control-03` —— ベースが決まった

ロースター内の 2 候補を、下流の学習コスト昇順(**結果と独立な基準**)で並べ、最初に関門を通ったものを採った。

```
候補① Llama-3.1-Swallow-8B-Instruct-v0.5 @ b1f83170
       正解率 0.6100 (≥0.30 ✅)   解釈不能率 0.75% (≤5% ✅)  → 凍結。候補②は測っていない
```

同じ書式・同じ変換経路・同じ器・同じ GPU 機種で、**ベースを 1.5B → 8B に替えただけで
解釈不能率が 14.50% → 0.75%。**雛形の `X` の字義取りは `Qwen2.5-1.5B-Instruct` の性質であって、
**書式 C の欠陥でも採点規則の厳しさでもなかった。**

以降のすべてのランはこのベースで回っており、GGUF sha256 `acb1ed7e…` は pc-03 から `lambda-ladder-01` まで
**ビット一致**している。

### 2.4 `positive-control-04` —— 梯子は全滅したが、落ちたのは 1 条件だけ

rank 32 は全滅し rank 64 は生き残る)。**この非単調性を説明する材料は、このアークには最後まで無い。**

### 2.5 `positive-control-05` —— 希釈仮説は否定された

pc-04 の x40 アームは設計上**埋め草が 0 トークン**で、学習信号の 100% が注入コーパスの書式だった。
そこで埋め草の割合 `f` だけを動かした(★ これは pc-04 の結果を見て思い付いた案ではなく、
**pc-02 が梯子を回す前に発動条件付きで表に書いておいた案**である)。

| 段 | f | 非注入 正解率 | 非注入 解釈不能 | 差 | a | b | c |
|---|---|---|---|---|---|---|---|
| 第0段 | — | 0.6250 | 0.00% | — | — | ✅ | ✅ |
| F1 | 0.50 | 0.0050 | 98.75% | +0.00 pt | ❌ | ❌ | ❌ |
| F2 | 0.75 | 0.1250 | 77.75% | +3.00 pt | ❌ | ❌ | ❌ |

**pc-04 と落ち方が違う。**pc-04 は c だけで落ちていたが、本ランは **a・b・c の 3 つとも落ちた。**
希釈は c を改善したが(98.75% → 77.75%)、**その代償に a を潰した。**

★ **埋め草は中立な詰め物ではなかった** —— 崩壊先が「注入コーパスの模倣」から「Wikipedia の模倣」に
移っただけである。loss も f とともに**上がった**(0.9117 → 1.1750)。pc-04 では E とともに単調に
下がっていたので、埋め草はそのぶん「覚えにくい」データだったことになる。

**F3(f = 0.875)は条件節の不等式連鎖が切れたので作っていない。**

### 2.6 `positive-control-06` —— λ を導入し、土台の再現に失敗して止まった

5 段は同一のアダプタから `α → λ·α` で作るので、pc-04・pc-05 に残っていた交絡が構造的に入らない。

**L0(λ = 1.0)は pc-04 R1 の再現確認の関門**だったが、そこで止まった。

| 指標 | pc-04 R1 の再現帯 | L0 の実測 | |
|---|---|---|---|
| 非注入群 正解率 | [0.384, 0.481] | **0.5700** | ❌ |
| 非注入群 解釈不能率 | [22.9%, 31.6%] | **8.25%** | ❌ |
| 差 | +8.4 pt 以上 | +18.25 pt | ✅ |

**L1〜L4 は 1 本も作っていない。**★ **数字は pc-04 R1 より良かったが、だから止めた**
(結果を見て規則を選ばない)。学習は再現していた(`train_loss` 0.2763194784 が一致)のに
測定値が動いた —— ズレはマージか量子化の段だと当時は読んだ。**これも後で覆る。**

★ **本ランは「梯子を回した末の全滅」ではないので、pc-06 が凍結した路線終了条件には該当しない**と
実行時に記録した(結果を見た後の言い訳ではない)。

### 2.7 `merge-variance-01` —— 前提のほうが崩れた

「アダプタは固定で、マージの作り方だけが動く」ことを測る設計だった。**第 3 手順(学習)で停止した。**

```
train_loss = 0.27621704663919366  (小数第4位 0.2762)   ≠  凍結値 0.2763   → 停止条件に該当
```

★ **一致しなかったのは `train_loss` だけである。**T 8,570,952 / ブロック 4,428 / steps 276 /
seed 20260809 / rank 32・α 64 / lr 2e-4 / micro 4 × grad_accum 4 / VRAM ピーク 35,126 MiB は
**すべて一致**した。**入力が同じで、学習の出力だけがずれた**(差 1.024e-04)。

**M1・M2・M3・M1b を作らず、測定を 1 回も行わず、R も D も計算せずに止めた。**
⛔ 予算では打ち切っていない。**規則で止めた**(約 1.6h / 上限 $15)。

★ **これで pc-06 の「学習は再現した」の読み方が 1 段弱まった** —— pc-04 は小数第 4 位までしか
記録を残しておらず、確かめられていたのは**その桁までの一致だけ**だった。記述は書き換えず、
preregister に但し書きを足した。

### 2.8 `train-determinism-01` —— ★ 学習は非決定的だった

同一コード・同一 seed・同一データ・同一機械で学習を 3 本(T1・T2・T3)回し、揺れそのものを測った。
**閾値 9.5 / 2.0 pt は `merge-variance-01` のものを 1 文字も変えずに引き継いだ**(本ランの数字を 1 つも見る前に)。

入力側(T `8,570,952` / ブロック `4,428` / steps `276`)は **3 本とも一致**した。
★ **それでもアダプタの sha256 は 3 本とも割れた。**

| 量 | 実測 | 判定表の行 |
|---|---|---|
| **V_loss** | `8.511e-05`(0.27633791 / 0.27642303 / 0.27637900) | 小数第 4 位で割れる → **学習は run ごとに非決定的** |
| ★ **V_meas** | ★ **18.00 pt**(非注入群 解釈不能率 **21.25 / 21.25 / 39.25**) | **「≥ 9.5 pt」** → ★ **過去の段ごとの合否はすべて読み直しが要る** |
| **D**(マージ経路の差) | **0.00 pt** —— T1d の GGUF が T1 と **sha256 までビット一致** | **経路の違いでは説明できない** |
| **T1 vs T1b** | **完全一致** | **推論は同一機械内で決定的** |

★ **着地点: pc-04 ↔ pc-06 の 19.00 pt は、学習の非決定性だけで 18.00 pt が説明される。**
推論もマージ経路もビット単位で決定的だったので、**差の出どころは学習に絞られた。**
`merge-variance-01` が追っていたマージ経路仮説は、ここで消えた。

⛔ **原因は特定していない**(bf16 の縮約順序 / cuBLAS の実行時ヒューリスティクス / 物理個体差 —— 未切り分け)。
⛔ **T3 だけが跳ねたことを「3 本中 1 本が壊れる」とは読まない**(n=3 では分布の形を言えない)。

★ **事前予測は、主判定 V_meas と着地点の両方で「確率を最も低く置いた側」が出た。**

★ **これで「単発の学習 1 本の測定値で段の合否を決める」設計が使えないことが確定した。**
同一条件の再現で 18.00 pt 動く量に、**5% の線**を当てていたことになる。

### 2.9 `ladder-reread-01` —— 過去の「全敗」を再現幅で読み直す($0)

**GPU を借りず、モデルを 1 本も作らず、測定を 1 回もしていない。**
★ 規則は commit `0bd86e4` で**結果を 1 文字も書かない状態で凍結してから**当てた。
⛔ **ただし数字はすでに全部見ているので、これは盲検の事前登録ではない。効いているのは規則の一様性だけである。**

再現幅 `W` は td-01 の実測の範囲そのままで、**補正は 1 つも掛けていない**:

```
W_a = 2.75 pt (差)   W_b = 13.00 pt (非注入 正解率)   W_c = 18.00 pt (解釈不能率)
```

| 対象 | 読み直しの結果 |
|---|---|
| **8 段のうち 7 段**(R0〜R4・F1・F2) | ★ **不合格は頑健**(落とした条件の余裕が `W` の外)。**「全滅」はこの 7 段については本物** |
| ★ **L0**(pc-06) | ★ **「不明」に落ちた** —— 落としたのは c だけで、余裕 **3.25 pt** が `W_c` = 18.00 pt の内側 |
| ★ **pc-06 を止めた関門の帯** | ★ **「不明」に落ちた** —— 正解率の余裕 8.90 pt / 解釈不能率の余裕 14.65 pt が**ともに `W` の内側** |

★ **帯は pc-04 R1 の測定 1 本のまわりに n=400 の二項 95% 区間として引いており、
学習の再現ばらつきを 1 pt も見込んでいなかった。構造的に狭かった。**

⛔ **合格に変わった段はゼロ**(「読み直しは不合格を不明にできるが合格にはできない」と先に凍結した)。
⛔ **「不明」は「合格の可能性がある」ではなく「確かめていない」である。**
★ **よって λ の梯子は否定されていない。L1〜L4 は未実行であって不合格ではない。**

★ **弱いところ**: `W` は n=3 の範囲なので真の幅を**過小評価する向き**であり、「頑健」と読んだ 7 段も
実際には不明かもしれない。⛔ 逆(不明が実は頑健)は起きにくい。

### 2.10 `replicate-judge-01` —— 判定の単位を変えた($0)

★ **「学習 1 本の測定 1 つ」を「同一設定の学習 k 本の分布」に置き換えた。**
複製の条件を先に当てて `k` = 5 を確定(pc-04 R1 / pc-06 L0 / td-01 T1・T2・T3)。
⛔ td-01 の T1b・T1d は独立な学習ではないので数えていない。⛔ **学習を 1 本も足していない。**

| 条件 | 読み 1(二値・k of k) | 読み 2(量・片側 95%・t 分布) | 判定 |
|---|---|---|---|
| **a** 差 ≥ 10 pt | **5/5**(`p ≥ 0.549`) | 平均 **14.90 pt** / 下側 **12.77 pt** | ★ **頑健に合格** |
| **b** 非注入 ≥ 0.30 | **5/5**(同) | 平均 **0.4730** / 下側 **0.4011** | ★ **頑健に合格** |
| ★ **c** 解釈不能 ≤ 5% | ★ **0/5**(`p ≤ 0.451`) | 平均 **23.45%** / 下側 **12.74%** | ★ **頑健に不合格** |

★ **3 条件とも 2 つの読みが一致 → `L0` は「不合格」で決着。**
`ladder-reread-01` が残した「不明」は、複製 5 本で解消した。

★ **着地点: 注入が効いていること自体は、複製 5 本で頑健に確認された**(差の下側限界 **+12.77 pt**)。
**この路線で初めて「複製で裏打ちされた合格」が出た**(条件 a と b)。

⛔ ★ **落ちているのは c(指示追従の破壊)だけ。**
★ **律速は「注入の弱さ」ではなく「指示追従の破壊」だと、解釈ではなく判定として確定した。**
★ **c を下げる未検証の軸は λ の梯子だけである**(pc-05 の希釈は a も潰れて否定済み)。

⛔ **弱いところ**: `k`=5 はドライバ 570 が 1 本・580 が 4 本で**機械間差が混ざっている**。
`p` の限界は 5 本とも通っても `≥ 0.549` までしか言えない。c の SD は **11.23 pt** と大きい。

### 2.11 `lambda-ladder-01` —— ★ L1(λ = 0.8)が頑健に合格した

★ **本ランは久しぶりに本当に盲検である**(λ < 1.0 の測定は 1 つも存在しなかった)。
★ **pc-06 の関門(過去ランとの再現帯)は置かず、判定を絶対的な a・b・c だけで行った** ——
`ladder-reread-01` が帯の構造的な狭さを示したためで、**これが pc-06 との最大の設計差である。**
★ **pc-06 の路線終了条件は、名前を変えて回避せずそのまま引き継いで凍結した。**

**λ = 0.8 の 3 複製**(各群 `n` = 400・原文条件・書式 C。3 本とも GGUF sha256 は別):

| 複製 | 非注入群 | 注入群 | **a 差** | **c 解釈不能率(非注入 / 注入)** |
|---|---|---|---|---|
| 1 | 0.6450 | 0.7575 | **+11.25 pt** | 0.25% / 0.75% |
| 2 | 0.6200 | 0.7650 | **+14.50 pt** | 0.00% / 0.25% |
| 3 | 0.6300 | 0.7650 | **+13.50 pt** | 0.50% / 0.50% |

- **読み 1(二値)**: a **3/3** / b **3/3** / c **3/3** → いずれも `p ≥ 0.368`
- **読み 2(量・片側 95%・`t`(2) = 2.920 / 必要余裕 1.686 × SD)**:
  a 平均 13.0833 pt・下側 **10.2771 pt** / b 平均 0.6317・下側 **0.6105** /
  c 平均 0.5000%・上側 **0.9215%** → **3 条件とも合格**

★ **2 つの読みが 3 条件とも一致 → `L1` は頑健に合格。凍結どおり最初の合格段で止め、
`L2`・`L3`・`L4` は作っていない。**

**効いた理由:**

| | λ = 1.0(`replicate-judge-01`・k=5) | λ = 0.8(本ラン・k=3) |
|---|---|---|
| a 差 平均 | 14.90 pt | **13.08 pt**(−1.82) |
| c 解釈不能率 平均 | **23.45%** | **0.50%**(−22.95) |
| c の SD | 11.23 | **0.25** |
| 判定 | **c で不合格** | ★ **合格** |

★ **λ を 1.0 → 0.8 にすると、差はほぼ保たれるのに指示追従の破壊だけが消える。**
`replicate-judge-01` の判定が、そのまま処方箋になった。

⛔ **事前予測は外れた** ——「合格する段は無い」6 割 /「通るなら L3(λ=0.4)」4 割に対し、
**最初の段で通った。**★ 当たった予測だけ書くと事前予測の意味が無くなるので、外れも記録に残す。

⛔ ★ **余裕をもって合格したのではない** —— a の実余裕 **3.0833 pt** に対し必要余裕 **2.8065 pt**、
**差は 0.28 pt しかない。**SD がもう少し大きければ `L1` は「不明」に落ちていた。

## 3. 何が言えて、何が言えないか

### 言えること

1. **λ = 0.8・レシピ R1・`f` = 0・このベース・この注入集合という条件で、
   a・b・c を同時に満たす陽性対照が 1 本作れる。**複製 3 本で裏打ちされている
2. **律速は注入の弱さではなく指示追従の破壊である**(`replicate-judge-01` の判定)。
   これは pc-04・pc-05 の全滅を統一的に説明する
3. ★ **同一コード・同一 seed・同一機械で学習を回しても、測定値は 18.00 pt 動く。**
   推論もマージ経路もビット単位で決定的なので、**出どころは学習に絞られている**
4. ★ **したがって「学習 1 本の測定 1 つ」で段の合否を決める設計は使えない。**
   判定は複製 k 本の分布で行う必要がある

### 言えないこと(★ 結果が出た後に 1 文字も広げていない)

1. ⛔ **「汚染検出器が効く」とは言わない。**手に入ったのは陽性対照であって、検出結果ではない
2. ⛔ **較正曲線・検出下限には 1 歩も進んでいない。**注入率を振っていない(40% 固定)。
   `70-positive-control.sh` は 1 度も走らせておらず、`drop` / `p_value` / `adjusted_lcb` は
   1 つも計算していない
3. ⛔ **`k`=3 なので、合格しても主張は `p ≥ 0.368` までである**(★ 「通る」と書かない)
4. ⛔ **同一インスタンス上の複製 3 本**なので、**機械間の差は入っていない**
5. ⛔ **λ を 4 点しか測っていない**(0.8 で通ったので 0.6 以下は未実行)。
   「λ = 0.8 が最適」とは言わない。**最初に通った段で止めただけである**
6. ⛔ **学習がなぜ非決定的なのかは特定していない**
7. ⛔ **崩壊が E・lr・rank に対して非単調である理由も説明していない**
8. ⛔ **HOLDOUT は開けていない。**K は 1/10 のままである
9. ⛔ **合格したレシピは「注入が入る条件」であって「現実的な汚染の強さ」ではない**
