# ▶ ステップ1(次にやること): Nejumi の**問題ごと**の正誤が取れるか調べる

**所要 1 時間。時間で打ち切る。** 目的は調査ではなく **可否の確定**。

## なぜ必要か

McNemar 検定は**不一致数 b, c**(通常○/摂動×、通常×/摂動○)を必要とする。
**平均正答率だけでは組めない。** 70% と 70% は、同じ問題を正解しているのか
まったく別の問題なのかで意味が正反対だが、平均はその差を消す。

## 成功条件(これが揃って初めて「取れた」)

1. **問題ごとの正誤**が取れる(集計スコアではなく 1 問 1 行)
2. **3パターンが同一の問題集合**に対応している(問題 ID で突き合わせられる)
3. **モデル横断**で同じことができる(最低 2 モデル。Holm 補正の対象になるため)

**3つ揃わなければ「不可」。** 部分的に取れた場合も、何が欠けたかを明記して「不可」に倒す。

# ステップ2(本命): 陽性対照を自分で作る

**まだ着手しない。**ステップ1を終えてから、**まず事前登録を書く。**

## 何をするか

ベンチマークの一部を意図的に学習させた**汚染モデルを自作**し、そこに contamlab を当てる。
「汚染されていないモデル」を探すのは不可能(無いことは証明できない)だが、
**汚染されていると分かっているモデルは作れる。** 先行研究の標準手順
(PaCoST は WMDP bio 1000 問で fine-tune している)。

## なぜこれが本命か

1. 公開した以上、「一度も陽性を出していない検出器」が最大の突っ込みどころになった
2. **HOLDOUT を消費しない。** 自作モデルが相手なので新規に事前登録して DEV で回せる
3. 注入量を変えた数水準を作れば**較正曲線**(入れた X / 測れた X̂)が得られる

## 副産物がおそらく本体 —— 較正済み汚染モデル一式

**注入量の ground truth 付きの汚染モデルを配っている人がいない。** 検出の論文はどれも
自前で作っては捨てている。標準として配れば後続が全員それで自分を測ることになる。

**これは問題集を持っていなくても作れる。** 前段の結論(稼げるのは問題を持っている側)と
噛み合い、立ち位置が「もう一つの検出器」(競合が強い)から
**「検出器を測る物差し」**(空いている)に変わる。

## 着手時の順序(飛ばさない)

1. [preregister.md](../preregister.md) に**測る前に**判定基準を書き、コミットする
2. モデル・注入水準・n を決める(検出力ゲートを通す)
3. 借りた計算資源で fine-tune → 測定 → `docs/` にランの報告書

**「結果を見てから規則を選ぶ」ことになるので、測定値・判定・n は後から変えない。**
これは全コミットで守ってきた規律。
